# Source access policies

This is a proposed enforcement contract; no source is activated. Each source has separately enabled capabilities for email, official API, feed, public HTML, browser automation and manual import, with permission evidence, review date and rate limits. Missing, expired or unknown permission defaults to deny automated access. Source enablement never authorizes every method. Central enforcement precedes dispatch, every redirect and authenticated session; external content and model output cannot change policy. Security review is required before a new adapter, scope or permission is activated. Test denied methods, missing evidence, redirect to denied host and rate limits deterministically.

LinkedIn direct scraping, automated browser access and unofficial APIs are prohibited. Use alerts, explicitly authorized official APIs, manual input or permitted alternatives. Authenticated portals including NS default to no automation until permission and terms are checked. Stop at challenges, CAPTCHA, access denial or revocation; no evasion, proxy rotation or credential harvesting. Playwright testing of our own UI is independent of external source policy.

Gmail is the intended first discovery adapter after CLI: least-privilege read-only OAuth, user-supplied configuration, configurable sender/label/query, minimized retention, proposed five-minute polling, durable checkpoints and message-ID deduplication. Delete Gmail text and evidence quotations when no longer needed for an active role, while preventing deletion of data still needed by another record. On disconnect, delete locally retained Gmail-derived text and quotations even for active roles. The lifecycle and safe deletion mechanism must be defined before activation; no automatic deletion is implemented yet. Handle pagination, expired credentials, missed intervals and invalid history checkpoints without silent loss. Push/watch is deferred; if introduced, handle renewal, duplicates and reconciliation. Review Google restricted-scope, consent, verification and security obligations before hosted distribution. Never scrape Gmail, send or modify messages.

For enrichment, try the original URL only if permitted, then authorized official APIs or permitted alternatives, recording claim-level provenance and completeness. Snippets are not full text; stale copies do not establish that a job is open. Preserve promising incomplete cases with a human verification request. Apply scheme, DNS/IP and redirect SSRF checks, timeouts, limits and sanitization.

Google sign-in and Gmail access are separate grants. `gmail.readonly` is a restricted scope that technically permits broad mailbox access; labels, sender allowlists and queries narrow processing, not the grant. Retrieve only relevant messages and necessary fields. Support encrypted server-side refresh tokens, revocation, reconnection and deletion; stop sync on invalid or revoked access. Securely bind mailbox to app user and explicitly confirm a different mailbox identity. A personal CLI may use a documented local OAuth flow before any dashboard exists. Review Google API Services User Data Policy and Gmail restrictions, disclosures, consent and processor handling before forwarding mailbox-derived data to an external AI provider; if compliance is uncertain, retain it locally or use manual import. Open source or user-owned credentials do not waive policy obligations.
