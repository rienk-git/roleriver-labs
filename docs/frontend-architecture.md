# Future static dashboard

The later independent dashboard uses React and Next.js App Router static export (`output: 'export'`). `next build` produces `out/`; build-time Server Components are allowed, runtime SSR, ISR, Server Actions, runtime Route Handlers, a Next.js-hosted BFF and a production Next.js server are not. A runtime SSR change requires an approved ADR. Verify pinned-version compatibility with [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports).

An independent TypeScript API owns business rules, authorization and runtime data; CLI and API share domain/application packages. OpenAPI generates a TypeScript client and validates boundaries. Use direct Google OIDC initially, with a separate optional Gmail authorization; an independently deployed TypeScript BFF, potentially part of the API, owns callbacks, server-side token refresh, sessions and authorization. The browser uses a Secure, HttpOnly application session cookie; Gmail refresh tokens stay encrypted server-side. Architect and security must review the concrete flow, cookie scope and SameSite policy, session lifecycle, CSRF and CORS before implementation; prefer same-origin routing where practical and protect state-changing requests against CSRF. Never expose refresh tokens or OAuth secrets to the browser, or store long-lived credentials in localStorage. Enforce ownership on every relevant endpoint, object download and worker operation. Use predeclared routes such as `/vacancy?id=123`, with Suspense where required, and verify deep-link refresh on the actual static host. Public demos use synthetic data only and no credentials.

Intended tools: TanStack Query, hooks/context, Tailwind and shadcn/ui; add Zustand, React Hook Form, Zod or Storybook only as useful. Test exported assets using mocked data with Vitest, React Testing Library, Playwright and axe-core; target WCAG 2.2 AA without claiming automated tests prove conformance. Acceptance covers overview, filters, detail, evidence/gaps, profile and source settings, sync/notification status, visible incompleteness, keyboard accessibility and deployed static refresh. No arbitrary score implies success probability. Explain client/server boundaries, hydration, hooks, caching and deployment trade-offs to the owner. Optional portals, Python and cloud do not block this milestone.

The public demo is synthetic and requires no Google login. Self-hosted users configure their own OAuth credentials; hosted multi-user operation is deferred pending policy and security review. Manual import remains available without Gmail consent. See [identity ADR](adr/008-google-identity.md).
