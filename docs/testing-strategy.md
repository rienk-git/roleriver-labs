# Testing and evaluation

Use red-green-refactor for deterministic business rules with synthetic fixtures and injectable time. Cover interval unions, date-only deadlines, alternatives, confirmed failures vs unknowns, provenance, source policy and deduplication. Schema and cross-language contract tests use shared fixtures when boundaries exist. Mock provider integration and CLI end-to-end tests run offline; invalid structured output and timeouts must fail safely. Never weaken tests to pass implementation.

Version synthetic AI evaluation fixtures and expected properties: evidence fidelity, classifications, legitimate alternatives, false-positive hard-requirement satisfaction, false-negative exclusions, unknown handling, recommendation consistency, prompt-injection resistance, latency and observed API usage/cost, not exact prose or scores. Compare model/prompt revisions on the same fixtures and report limitations. Live evaluations are opt-in, separately billed and excluded from default CI. Future CI runs frozen install, format, lint, typecheck and tests; coverage targets focus on critical behavior rather than an arbitrary percentage. QA reviews acceptance independently when warranted; no tests or CI exist yet.

At persistence milestone, isolated DynamoDB Local integration tests exercise conditional deduplication, pagination, ownership, retries and documented access patterns; shared object-storage behavioral tests cover authorization boundaries and retry-safe recovery. Default unit/CLI tests remain offline without AWS or Google credentials. Mock auth tests cover invalid/expired ID tokens, callback/state failures, Secure and HttpOnly cookie attributes, session rotation/expiry/logout, CSRF, token isolation and cross-user access including object downloads and worker processing. Mock Gmail tests cover optional consent, refresh/revocation, scoped ingestion and checkpoint recovery. Emulator tests do not establish AWS IAM, encryption, TTL or deployment equivalence. Static export and synthetic-only demo are tested independently of a Next.js runtime server.

Acceptance cases: Symfony satisfying an allowed Laravel alternative with evidence; explicit lack of mandatory Kotlin versus missing Kotlin; coaching alone not establishing a three-year techlead role; contextual DevOps/application responsibilities; Kubernetes as preference; overlapping experience periods; high score with a confirmed unmet hard requirement; incomplete restricted-portal summary; warm-seat warning; confirmed expired deadline before paid assessment; invalid or contradictory output; and injection in either CV or vacancy. Mock provider responses for deterministic contract and failure tests; semantic quality is evaluated rather than asserted as exact model prose.
