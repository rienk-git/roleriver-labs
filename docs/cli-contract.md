# Proposed CLI contract

Not implemented. Illustrative invocation: `roleriver assess --cv <path> --vacancy <path> [--preferences <path>] --format text|json`. CV and vacancy text suffice; optional input supplies structured preferences and clearly labelled supplementary evidence or corrections. Vacancy metadata can record source, completeness, status and dates. Exact file formats, option syntax, schema and exit codes remain to be agreed. The CLI needs no database, Google login, Gmail, browser or cloud infrastructure.

A narrow OpenAI provider adapter makes one logical structured assessment request, using a versioned prompt and output schema; bounded retries are observable. Default offline tests use a mocked provider; live assessment is opt-in, separately billed and uses user-supplied local credentials. Known objective disqualifiers may be checked before a paid call.

Output provides original requirement text and evidence, classified assessments and candidate references, gaps, disqualifiers, uncertainty, completeness/status warnings, recommendation, disposition and versioned provenance. Optional scores are indicative, not probabilities or sole notification gates. JSON is versioned; text conveys equivalent material facts. Validate schema, resolvable references and consistency; schema validity does not prove truth. Unknown evidence is not failure. No private text is logged by default.

Unreadable or invalid input, provider failure/timeout, invalid or contradictory output and unresolved required evidence yield controlled errors or explicit unknown outcomes, never fabricated success. Acceptance: a synthetic CV and vacancy exercise a complete offline mocked-provider vertical slice; deterministic rules, evidence references and error paths are tested; output validates; live calls require explicit opt-in.

## C02 domain boundary

The local `assessmentInputSchema` validates nonblank CV and vacancy strings without trimming the supplied source text. Optional supplements and corrections are labelled separately; preferences and vacancy metadata are optional. This is an in-process input shape, not a finalized file format or CLI interface. Deadline metadata requires explicit `verified: true` before objective evaluation can report expiry; absent or false verification stays unknown. Nonblank but malformed date text is preserved as source data and evaluates to unknown; structurally invalid metadata fails validation. Callers must establish verification independently of model output.

For verified timestamps with an explicit offset, the stated instant is inclusive: expiry starts strictly afterwards. Date-only deadlines require an explicit valid time zone and remain valid for the entire local calendar day; without it, expiry is unknown. The caller supplies the current time. Reliable experience intervals are half-open `[start, end)` in integer UTC epoch milliseconds; callers must not infer exclusive boundaries from ambiguous source dates. Numeric threshold comparisons require both values to be verified, finite and in identical explicit units; minimum and maximum boundaries are inclusive. A caller must determine independently that a constraint is mandatory: preferences alone are not exclusions. These helpers do not perform semantic matching or make a final recommendation.

## C03 provider boundary

`OpenAIAssessmentProvider` sends one structured Responses API request using a caller-supplied API key and model, fixed versioned instructions, no tools, `store: false`, an abortable timeout and no automatic retries. The caller must minimize data and determine external-processing authorization independently; passing `allowed` is a gate, not proof of policy compliance. In particular, do not forward Gmail-derived content until the applicable restrictions in [source policies](source-policies.md) have been satisfied. No live API request was made in C03.

The adapter validates the output shape, unique requirement IDs, exact evidence excerpts and source references, score range, completeness and contradictions before returning a result. It requires candidate evidence for `met` and `not_met` and will not return `apply` for incomplete vacancies, disqualifiers or non-met hard requirements. A matching excerpt is not proof of the model's interpretation; independent evaluation remains necessary. Successful results record model, prompt/schema versions, input hashes and timestamp; these hashes are sensitive derived data and must not be logged or published by default. Errors return controlled categories without raw provider details. No persistence, cache, CLI or automatic data redaction is implemented.

### Optional live evaluation

The default `pnpm test` excludes `*.live.test.ts` and needs no credentials. An optional, separately billed live evaluation uses only the versioned synthetic fixture in `packages/ai/evals/assessment.live.test.ts`. Configure `OPENAI_API_KEY` securely outside the repository and set `ROLERIVER_OPENAI_MODEL` to a model that supports Responses structured outputs. Then deliberately opt in with `ROLERIVER_LIVE_EVAL=1 pnpm eval:live`. The evaluation fails before a provider request if opt-in or required configuration is missing. Results are behavioral checks, not calibrated accuracy; no live run has been performed for C03. Never put real candidate or vacancy content in this fixture.
