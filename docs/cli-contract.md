# Matching CLI contract

The CLI reads UTF-8 CV and vacancy text (at most 1 MiB per file); a structured candidate profile is not required. Build with `mise exec -- pnpm build` and run `mise exec -- node dist/apps/cli/main.js assess --cv <path> --vacancy <path> --format text|json` with the necessary flags below. An optional `--details <json-file>` supplies preferences, `supplementaryEvidence` and `vacancyMetadata` using the C02 schema. Exact type definitions are in `packages/domain/input.ts`; `--help` describes the flags.

A provider call requires all three flags: `--live` explicitly opts into a separately billed OpenAI request; `--confirm-manual` attests that all input is manually supplied and contains no Gmail-derived content; `--confirm-minimized` attests that the input has been minimized/redacted and is authorized for external processing. These flags are operator attestations, not automated redaction or proof of policy compliance. Do not use Gmail-derived content through this path. An explicit `--confirm-deadline` asserts the supplied deadline was personally verified; a metadata `verified` value alone is not trusted. A confirmed expired deadline is returned locally before credentials or a provider call.

For a live call, supply `OPENAI_API_KEY` securely through the environment or a local secret manager and set `ROLERIVER_OPENAI_MODEL` to a model supporting Responses structured outputs. Never put keys in arguments, source control, logs, or the browser. Use a dedicated project key with least privilege and an expiration; rotate by creating and verifying a replacement before revoking the old key, and revoke immediately if exposed. [OpenAI key guidance](https://developers.openai.com/api/docs/guides/api-keys). No credentials are needed for the offline tests or deadline preflight.

JSON output is versioned; text output includes the same assessment and evidence as formatted JSON. Using `node` directly avoids package-manager banners on JSON stdout. Results distinguish the model recommendation and evidence-backed role-alignment assessment from the application disposition. A confirmed expired deadline produces `unsuitable`; unconfirmed model concerns or insufficient alignment leave `disposition` as `null` with `reviewRequired: true`; otherwise an evidence-backed model assessment of role alignment can remain `potentially_promising`, including when vacancy text is partial; all non-expired assessments require review because the vacancy’s open status is unverified. Model output is not independently confirmed proof. Unknowns remain explicit; optional scores are indicative, not probabilities or notification gates. Output may contain private quotations and hashes: handle it as sensitive data.

Invalid input/options, unreadable/oversized files and provider errors return nonzero status and sanitized stderr without raw content or secrets. No applications, notifications or network requests occur without the explicit live flags. Tests use a mocked provider; no live C04 assessment has been run.

## C02 domain boundary

The local `assessmentInputSchema` validates nonblank CV and vacancy strings without trimming the supplied source text. Optional supplements and corrections are labelled separately; preferences and vacancy metadata are optional. This is an in-process input shape, not a finalized file format or CLI interface. Deadline metadata requires explicit `verified: true` before objective evaluation can report expiry; absent or false verification stays unknown. Nonblank but malformed date text is preserved as source data and evaluates to unknown; structurally invalid metadata fails validation. Callers must establish verification independently of model output.

For verified timestamps with an explicit offset, the stated instant is inclusive: expiry starts strictly afterwards. Date-only deadlines require an explicit valid time zone and remain valid for the entire local calendar day; without it, expiry is unknown. The caller supplies the current time. Reliable experience intervals are half-open `[start, end)` in integer UTC epoch milliseconds; callers must not infer exclusive boundaries from ambiguous source dates. Numeric threshold comparisons require both values to be verified, finite and in identical explicit units; minimum and maximum boundaries are inclusive. A caller must determine independently that a constraint is mandatory: preferences alone are not exclusions. These helpers do not perform semantic matching or make a final recommendation.

## C03 provider boundary

`OpenAIAssessmentProvider` sends one structured Responses API request using a caller-supplied API key and model, fixed versioned instructions, no tools, `store: false`, an abortable timeout and no automatic retries. The caller must minimize data and determine external-processing authorization independently; passing `allowed` is a gate, not proof of policy compliance. In particular, do not forward Gmail-derived content until the applicable restrictions in [source policies](source-policies.md) have been satisfied. No live API request was made in C03.

The v2 prompt and output schema include a model-assessed role-alignment status and source quotations for vacancy responsibilities and candidate context. The adapter validates the output shape, unique requirement IDs, exact evidence excerpts and source references, score range, completeness and contradictions before returning a result. It requires candidate evidence for `met` and `not_met` and will not return `apply` for incomplete vacancies, disqualifiers or non-met hard requirements. A matching excerpt is not proof of the model's interpretation; independent evaluation remains necessary. Successful results record model, prompt/schema versions, input hashes and timestamp; these hashes are sensitive derived data and must not be logged or published by default. Errors return controlled categories without raw provider details. No persistence, cache or automatic data redaction is implemented.

### Optional live evaluation

The default `pnpm test` excludes `*.live.test.ts` and needs no credentials. An optional, separately billed live evaluation uses only the versioned synthetic fixture in `packages/ai/evals/assessment.live.test.ts`. Configure `OPENAI_API_KEY` securely outside the repository and set `ROLERIVER_OPENAI_MODEL` to a model that supports Responses structured outputs. Then deliberately opt in with `ROLERIVER_LIVE_EVAL=1 pnpm eval:live`. The evaluation fails before a provider request if opt-in or required configuration is missing. Results are behavioral checks, not calibrated accuracy; no live run has been performed for C03. Never put real candidate or vacancy content in this fixture.
