# Threat model

Candidate evidence, email, tokens and browser sessions are sensitive. Vacancy content and URLs are untrusted; an attacker could attempt prompt injection, SSRF, credential disclosure or resource exhaustion. A compromised dependency or workflow could expose secrets. In a later browser/API, authentication, CSRF, CORS and authorization require explicit design.

Controls: keep private data outside Git; least-privilege OAuth and runtime-only secrets; redact logs and minimize model input; validate schemas and isolate untrusted content from instructions and tools; default-deny source/method/redirect policy; block unsafe URL schemes and private/reserved destinations, recheck DNS and redirects, cap sizes and timeouts; review dependencies and enable available secret scanning. Never bypass access controls. Delete user-requested local data, tokens and derived artifacts through documented procedures when persistence exists; exact retention periods and deletion implementation remain open. AI provider retention and data handling must be reviewed before real data is sent. Security review is required for relevant changes, not a claim of security certification.

The future API must isolate users by internal ID mapped from validated OIDC issuer and subject; enforce ownership for endpoints, object downloads and workers. The independent BFF isolates provider tokens and refreshes them server-side; the browser receives only a Secure, HttpOnly application session cookie. Review code/PKCE, state, redirect, ID-token verification, cookie scope and SameSite, session rotation and expiry, CSRF and CORS with security before implementation. Protect state-changing requests against CSRF even with same-origin routing. Keep Gmail credentials separate from ordinary data, encrypted at rest with restricted access and AWS KMS-backed protection in AWS; never expose refresh tokens to the browser. Handle revocation, refresh failure and connection deletion. Protect private objects independently of public frontend assets. Cross-store writes need recovery and orphan cleanup; conditionals protect concurrent duplicate handling. Least-privilege IAM, encryption, retention and deletion need authorized AWS validation; local emulators cannot prove them.

The matching provider receives only relevant CV and vacancy data after unnecessary identifiers and unrelated sensitive content are redacted. Treat both as hostile data, never instructions or tool authority. Validate output schema, evidence references and consistency, while recognizing these checks do not establish factual truth. Keep raw inputs out of logs. Apply Gmail external-processing restrictions before any provider call.
