# Agent workflow and compatibility

Installed CLI observed: `codex-cli 0.162.0-alpha.17.2`. Official [subagent documentation](https://developers.openai.com/codex/multi-agent) describes standalone `.codex/agents/*.toml` with `name`, `description`, `developer_instructions`, and project `[agents] max_concurrent_threads_per_session`; the older `max_threads` is a legacy alias. Model overrides are optional. Agent files inherit parent permissions; `sandbox_mode` and approval policy inside them do not override the parent. Read-only review is therefore an instruction, not a guaranteed sandbox. Exact support of the current documentation's schema in this alpha build remains unverified until a trusted project session loads it; do not assume a TOML syntax check proves discovery or enforcement.

Ask Codex CLI or IDE to use a named specialist with a narrow task and expected output. If custom roles are unavailable, manually apply each role sequentially in separate review contexts where feasible; disclose the fallback. No specialist was invoked in this bootstrap because the preferred lightweight model and inheritance of an explicitly selected lightweight parent were not established. A potential alternative visible to this session is `gpt-6-luna`, but its suitability and account availability require owner approval before selection.

Assign explicit nonoverlapping files and contracts; use isolated worktrees for concurrent writes or serialize. Never concurrently edit shared files or lockfiles. No nested delegation by default. Specialists return scope, files, checks actually run, risks and questions. The orchestrator integrates, runs relevant gates, updates roadmap/log and presents material architecture/security decisions for human approval. Security reviews auth, secrets, external content, fetching, permissions and sensitive data; DevOps reviews relevant delivery changes. Read-only reviews do not establish organizational independence or guarantee correctness.
